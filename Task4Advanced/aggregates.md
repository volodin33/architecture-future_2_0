# Агрегаты доменов

По одному ключевому агрегату на основные домены: границы, инварианты, ключ.

## Patient (Пациентский поток)
- **Ключ:** `patient_id`
- **Границы:** профиль пациента и факт регистрации/приёма. Медкарты и результаты исследований в агрегат **не** входят (хранятся в медсистеме, в аналитику не идут).
- **Инварианты:** пациент уникален по идентификатору; нельзя начать приём для незарегистрированного пациента.

## AIInvestigation (ИИ-сервисы)
- **Ключ:** `investigation_id`
- **Границы:** заявка на ИИ-анализ и его статус/итог (факт прохождения, без чувствительного содержимого).
- **Инварианты:** анализ привязан к существующему пациенту; результат публикуется только после завершения.

## CreditContract (Финтех)
- **Ключ:** `contract_id`
- **Границы:** кредитный договор, сумма, ставка, статус.
- **Инварианты:** сумма > 0; договор оформляется на существующего клиента; статус меняется только по допустимым переходам (черновик → активен → закрыт).

## Invoice (Финтех)
- **Ключ:** `invoice_id`
- **Границы:** счёт, позиции, сумма, статус оплаты.
- **Инварианты:** итоговая сумма = сумме позиций; нельзя оплатить уже оплаченный счёт.

> Каждый агрегат — единица согласованности: изменения внутри атомарны, между агрегатами/доменами связь только через события (см. [events.md](./events.md)).
