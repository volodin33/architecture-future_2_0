# План управления рисками

Для каждого риска из [risks.md](./risks.md) — мера снижения и её тип: **техническая** (T) или **управленческая** (M).

## Меры по рискам

| ID | Мера снижения | Тип |
|----|---------------|:---:|
| A1 | Поэтапный вынос логики из DWH через ACL; постепенное замещение, а не разовая переписка | T + M |
| A2 | Идемпотентные потребители, ключи дедупликации, явная политика согласованности; обучение команд паттернам EDA | T + M |
| A3 | Чёткие границы контекстов (Task4), запрет на общие БД между доменами, контрактное взаимодействие только через события | T + M |
| A4 | Schema Registry с версионированием и проверкой совместимости (обратная/прямая) | T |
| O1 | Назначение ролей Data Product Owner / Data Engineer / BI-аналитик; обучение и наём | M |
| O2 | Пилот на 1–2 доменах с быстрым результатом; вовлечение пользователей, демонстрация выгод self-service BI | M |
| O3 | Каталог дата-продуктов с явным владельцем и SLA на каждый продукт | T + M |
| O4 | Дорожная карта с измеримыми вехами по 3 этапам; регулярный пересмотр границ легаси | M |
| T1 | Шифрование, маскирование/исключение чувствительных полей, RBAC, аудит доступа; согласование с регуляторами | T + M |
| T2 | CDC-инструменты для постепенной выгрузки из SQL Server, валидация и сверка данных, параллельный прогон | T |
| T3 | Ставка на открытые стандарты (S3 API, Kafka, открытые форматы таблиц), IaC для переносимости | T |
| T4 | Замещение PowerBuilder доменными сервисами и порталом self-service BI; вывод из эксплуатации по плану | T + M |
| T5 | Transactional Outbox, DLQ, ретраи, мониторинг доставки событий | T |

Тип меры: **T** — техническая (ACL, Schema Registry, идемпотентность, Outbox/DLQ, шифрование/RBAC, CDC, IaC), **M** — управленческая (роли Data Mesh, обучение, пилот, SLA дата-продуктов, дорожная карта, комплаенс с регуляторами).

## Привязка к этапам трансформации
- **Этап 1 (0–6 мес):** заложить технический фундамент против T1, T5, A4 (schema registry, DLQ, RBAC) и организационный против O1, O2 (роли, пилот).
- **Этап 2 (6–18 мес):** ACL и постепенное замещение против A1, T2, T4; контроль границ доменов A3.
- **Этап 3 (18–36 мес):** вывод легаси (A1, T4), снижение привязки к поставщику T3, доменная аналитика.
